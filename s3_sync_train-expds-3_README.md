# Скачивание и докачка датасета `train-expds-3` (Selectel S3)

Один скрипт вместо прежних двух (`boto3_download_train-expds-2.py` и
`participant_download_s3_data.py`) — с режимами **скачивания** и **докачки нового**.

```
s3_sync_train-expds-3.py
```

## 1. Что нового по сравнению с прежними скриптами

| Возможность | Прежние скрипты | Этот скрипт |
|---|---|---|
| Режимы | один (скачивание + сверка) | `update` (докачка нового), `download` (скачивание), `verify` (только проверка) |
| Обрыв на большом файле | файл качался заново целиком | **докачка с середины** по HTTP Range, `.part` сохраняется |
| Повтор после Ctrl+C | терялся весь прогресс файла | запустили ту же команду — продолжилось с места обрыва |
| Контроль целостности | только размер | размер + `--md5` (в т.ч. для больших составных файлов) |
| Мусор от прерванных загрузок | чистился только при старте | чистится автоматически, с привязкой к версии файла |
| Отчётность | лог-файл | лог-файл + CSV-отчёт + прогресс со скоростью и ETA |

## 2. Требования

Нужен Python 3.8+ и библиотека `boto3`:

```bash
pip install boto3
```

В этой системе готовый интерпретатор с `boto3` уже есть:

```bash
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --help
```

## 4. Быстрый старт

**Первое скачивание (и оно же — докачка, режим по умолчанию):**

```bash
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --local-dir ./train-expds-3
```

**Если загрузка прервалась** — просто запустите ту же команду ещё раз.
Незавершённые файлы продолжатся с того места, где остановились:

```bash
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --local-dir ./train-expds-3
```

**Проверить, всё ли скачано (ничего не качает):**

```bash
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --mode verify --local-dir ./train-expds-3
```

> Совет: указывайте `--local-dir` отдельной папкой (`./train-expds-3`), чтобы
> данные нового датасета не смешивались с уже лежащими папками КОЗ2.

## 5. Режимы

| Режим | Поведение |
|---|---|
| `--mode update` (по умолчанию) | **Докачка нового.** Качает только то, чего нет локально, и то, у чего изменился размер. Уже скачанные корректные файлы не трогает никогда (даже с `--force`). |
| `--mode download` | **Скачивание.** То же, но с `--force` перекачивает и уже существующие корректные файлы. |
| `--mode verify` (или `--verify-only`) | **Только проверка.** Ничего не скачивает и не удаляет, печатает сводку расхождений. |

Скрипт возвращает код `0` при успехе, `1` при ошибках/расхождениях, `130` при
прерывании по Ctrl+C — удобно для запуска из своих скриптов и cron.

## 6. Основные параметры

| Параметр | Смысл |
|---|---|
| `--local-dir DIR` | куда сохранять (по умолчанию — текущая папка) |
| `--folder PREFIX` | скачать только папку/префикс, например `--folder 001_Гнёздово_Нивленское` |
| `--threads N` | число параллельных загрузок (по умолчанию 4) |
| `--force` | в режиме `download` — перекачать всё заново |
| `--skip-changed` | качать только новые файлы, изменившиеся не трогать |
| `--no-resume` | не докачивать `.part`, начинать каждый файл с нуля |
| `--retries N` | попыток на файл при ошибках сети (по умолчанию 6) |
| `--md5` | сверять контрольную сумму с ETag объекта (см. §8) |
| `--no-verify` | не проверять результат после скачивания |
| `--dry-run` | показать план и ничего не качать |
| `--report FILE.csv` | записать CSV-отчёт (что скачано/пропущено/ошибки) |
| `--log-file FILE` | путь к логу (по умолчанию `s3_sync_train-expds-3.log`) |
| `--exclude ИМЯ` | исключить папку с таким именем (по умолчанию `Старая`, `Архив`; можно повторять) |
| `--tls-verify` | проверять TLS-сертификат сервера (по умолчанию проверка отключена, как в прежних скриптах) |

## 7. Как работает докачка

1. Файл пишется потоково (порциями по 8 МиБ) не сразу в целевой путь, а во временный
   `<имя>.<отпечаток ETag>.<размер>.<версия>.part`.
2. Имя `.part` содержит признак версии объекта. Поэтому докачка **физически не может**
   склеить куски разных версий файла: если объект на сервере обновился, старое имя не
   совпадёт и файл будет скачан заново.
3. Перед началом работы скрипт удаляет `.part`-файлы, которые уже нельзя использовать
   (объект обновился или исчез, либо финальный файл уже на месте), а также временные
   файлы прежнего скрипта вида `<имя>.<8 hex>`.
4. При обрыве сети, выключении питания или Ctrl+C `.part` остаётся на диске, и при
   следующем запуске загрузка продолжается с текущего размера через заголовок
   `Range` (проверяется код ответа `206`; если сервер диапазон не поддержал —
   файл честно качается заново).
5. Когда файл докачан полностью и его размер совпал с серверным, `.part`
   переименовывается в целевое имя (атомарно, в пределах одной папки).

Дополнительно: 6 попыток на файл с экспоненциальной задержкой (3→6→12→24→30 с плюс
случайный разброс), так что кратковременные сбои сети загрузку не роняют.

## 8. Проверка целостности

* **Всегда** (и после скачивания, и в режиме `verify`) сверяется размер файла.
* **С `--md5`** дополнительно сверяется контрольная сумма с ETag объекта:
  * если объект залит одним куском — ETag это MD5, считается MD5 локального файла;
  * если объект залит частями (большие `.tif`/`.las`) — локально пересчитывается
    составной ETag (MD5 от конкатенации MD5 частей, размер части подбирается из
    стандартных значений).

> **Важная особенность Selectel.** `list_objects_v2` в этом хранилище отдаёт для
> составных объектов **некорректный (усечённый) ETag** — он не равен MD5 файла.
> Поэтому скрипт берёт ETag через `head_object` и никогда не сверяет MD5 по данным
> листинга. ETag из листинга используется только как непрозрачный признак версии
> в имени `.part`.

Проверка с `--md5` читает весь объём данных с диска (для полного датасета — 199 ГиБ),
поэтому это заметно дольше обычной сверки по размерам. Разумный сценарий: обычная
докачка без `--md5`, а `--md5` — периодически или для подозрительных файлов:

```bash
# проверить только одну папку
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --mode verify --md5 \
    --folder 001_Гнёздово_Нивленское --local-dir ./train-expds-3
```

## 9. Прогресс, лог, отчёт

Во время работы печатается строка вида:

```
  Прогресс: [211/1053]  38.4% | 76.42 GiB/199.43 GiB | 25.10 MiB/s | осталось ~1:23:41
```

Скорость считается по реально принятым из сети байтам (уже лежащие на диске файлы
её не завышают). По завершении выводится сводка: сколько новых, обновлённых,
перекачанных, пропущенных, ошибок, сколько принято по сети и за какое время.

Отчёт в CSV (удобно открывать в Excel, разделитель `;`, кодировка UTF-8 с BOM):

```bash
~/.venvs/koz3/bin/python s3_sync_train-expds-3.py --report sync_report.csv \
    --local-dir ./train-expds-3
```

## 11. Частые вопросы

**Можно ли просто запускать скрипт по расписанию?**
Да. Режим `update` по умолчанию докачивает только новое и ничего не удаляет.
Запуск на уже синхронизированной папке завершается сообщением
«Всё уже скачано» и кодом `0`.

**Сколько потоков ставить?**
Начните с 4–8. Больше потоков помогает на множестве мелких файлов и не помогает
на одном большом (каждый файл качается в один поток, зато с докачкой).

**Сколько нужно места на диске?**
~200 ГиБ на сам датасет плюс запас на незавершённые `.part`.

**Файлы на сервере обновились, но размер тот же — увидит ли скрипт?**
По размеру — нет (как и прежние скрипты). Такой файл можно найти через
`--mode verify --md5`, а затем удалить локально и докачать.

**Скрипт удаляет мои файлы?**
Нет. Ничего, кроме своих `.part` и временных файлов прежнего скрипта
(`<имя>.<8 hex>`), он не удаляет; лишние локальные файлы только показываются
в отчёте `verify`.

**Ошибка `Не найден boto3`** — установите библиотеку (`pip install boto3`) или
запускайте через `~/.venvs/koz3/bin/python`.

**Windows** — запускайте `python s3_sync_train-expds-3.py ...`; вывод в консоль
принудительно переводится в UTF-8, имена файлов с кириллицей обрабатываются
корректно.
